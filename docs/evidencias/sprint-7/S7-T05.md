## Checklist tecnico executavel

- FastAPI debug=False; CORS nao libera origem arbitraria nem credenciais;
  browser conversa com WP no mesmo origin e Bridge fala com API no servidor.
- HMAC, nonce, autorizacao por objeto, limites e logs: suites S1-S6 mantidas.
- Proxy: peer confiavel explicito, XFF de peer externo ignorado; Uvicorn nao
  interpreta proxy headers automaticamente. Nao configurar redes irrestritas.
- TLS PHP: sempre validado; redirects HTTP da Bridge continuam bloqueados.
- Permissoes: capability especifica, identidade server-side, admin allowlist
  separada no backend, acesso por objeto preservado.
- Segredos: bootstrap aleatorio local, .demo e .env ignorados, imagens nao
  copiam .env/venv; scanner de arquivos rastreados detecta .env/.demo,
  private keys, tokens GitHub e AWS access IDs sem imprimir valores.
  Esse scanner e direcionado: nao e auditoria completa do historico/entropia.
- Runtime demo: verifica WP_DEBUG/DISPLAY/LOG false, edicao de arquivos
  desligada, preview off, chave configurada, PHP display off e API non-root.
- Nenhuma tag, release publicada ou merge foi executado.

## Limites funcionais revelados pela revisao

GETs WordPress de animais, parametros e historico de fechamentos eram apenas
arrays demonstrativos, sem consulta real ao backend. Agora retornam
DEMO_ONLY_UNAVAILABLE/503 fora do preview explicitamente permitido. Manejos
sem lote tambem nao retornam dados simulados. Escritas nunca devem indicar
sucesso quando a API esta offline. A interface contem dados ilustrativos
anteriores (documentados desde S3); nao declarar toda a UI como integrada com
base no smoke test de fazendas/certificado. Joao deve revisar esses pontos
no checklist funcional antes de liberar a tag, junto ao QA de Nadiny.
